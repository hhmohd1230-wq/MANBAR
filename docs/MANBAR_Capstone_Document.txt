1. PROJECT OVERVIEW
================================================================

1.1 What MANBAR is
MANBAR (Arabic "منبر", meaning "the stage" or "the pulpit") is a campus-only web platform where a student's idea can grow into a post, a project team, a paid or free service, a course, or a portfolio entry. It starts at Al Ain University and is designed to add more universities (for example Abu Dhabi University and UAE University) and later open to the public.

1.2 The problem it solves
Students today use many separate apps: LinkedIn for profiles, Fiverr for services, Discord or WhatsApp for teams, and Moodle for courses. None of them are limited to verified students of one university, and none connect an idea to a team, a service and a course. MANBAR puts these pieces in one place behind a university-only sign-in, so everyone on the platform is a verified student or teacher.

1.3 Main goals
- Give every student a stage to share ideas and get feedback.
- Help students form project teams with the right skills and finish real projects.
- Let students earn money or help each other through a safe student marketplace.
- Let teachers and top students teach through step-by-step courses with quizzes and live games.
- Reward real contribution with reputation XP, ranks, badges, vouches and a trust score.
- Give administrators full control: moderation, bans, scam cases, roster and analytics.

1.4 Users and roles
| Role    | Who                                   | Extra abilities |
| Student | Anyone signing in with a student-number university email | Post, join projects, buy/sell services, enroll in courses, request mentors. Students who reach the Gold rank (900 XP) can also create courses. |
| Teacher | University staff (name.surname@ email) | Create courses, announcements and teaching offers, mentor profile. |
| Admin   | Platform administrators               | Admin console: analytics, users, bans, XP and badges, roster, moderation, scam cases, universities, settings and audit log. |

2.2 Why no framework
The team chose plain PHP with a small custom core (about 15 helper files) instead of Laravel or React. Reasons:
- It runs on any shared host or XAMPP with no build step.
- Every part of the code is understandable and explainable at the defense.
- Pages load fast: no large JavaScript bundles; all assets are plain CSS/JS/SVG files.

2.3 PHP techniques used
- Front controller: every request goes through public/index.php.
- Custom router: app/routes.php lists 177 routes as [METHOD, '/path/{param}', 'handler'] and the router converts them to regular expressions.
- Controllers: one PHP file per module in app/controllers/ (feed, profile, projects, market, pay, learn, quiz, live, mentors, social, settings, admin, admin_tools, auth).
- Views: PHP templates in app/views/ with a shared layout (layout.php), a public layout (layout_public.php), an admin layout (admin/layout.php) and reusable partials (post card, comments, service card, step bar, materials gallery, notifications list, scam report form and more).
- Database helpers: qall(), qrow(), qval(), qexec(), insert(), update() wrap PDO prepared statements.
- Self-updating schema: ensure_*_schema() functions add new tables and columns automatically the first time a feature is used, so the database upgrades itself without manual migrations.
- Security helpers: e() for HTML escaping, CSRF tokens, password_hash(), finfo MIME checks.
- Server-to-server HTTP calls (cURL / streams) to Google, Stripe and AI providers.
- ZipArchive for reading Word (.docx) quiz files and generating demo documents.

3.2 Request flow
1. The browser requests a URL, for example /marketplace/8.
2. Apache sends it to public/index.php (mod_rewrite).
3. index.php loads app/bootstrap.php (configuration, helpers, database, all controllers), starts a secure session and sets security headers.
4. For POST requests the CSRF token is verified (from the form field or the X-CSRF-Token header).
5. The router finds the matching route and calls the handler, for example page_service(8).
6. The handler checks the login and permissions, reads the database and calls render('service', data).
7. render() fills the view template and wraps it in the layout (sidebar, top bar, notifications, scripts).
8. API routes (/api/...) return JSON instead of HTML for live features (reactions, comments, notifications, messages, AI assistant, live quiz state).

3.3 Live features without WebSockets
Live parts use short polling with fetch():
- Unread counters for notifications and messages refresh every 45 seconds (/api/counts).
- Direct messages and the typing indicator refresh every few seconds (/api/messages/{id}).
- Live quizzes: players and host poll the game state (/live/{code}/state and /live/{code}/host/state).

4.1 AI engine order and privacy
The assistant tries the engines in this order: Gemini, then Groq, then OpenAI, then Claude, then MANBAR's own local PHP engine. Only text that the user explicitly sends with an assistant button goes to an AI provider. Checks while typing stay local. Database passwords and private records are never sent to a model. Searching MANBAR's own posts, projects, people, mentors, courses and services is done by the PHP backend, not by the AI. The assistant is limited to 30 requests per minute per user to prevent abuse.

4.2 Payment providers shown in the checkout
The checkout page shows Visa, Mastercard, American Express, Apple Pay, PayPal and tabby (pay in 4). Card payments for courses go through Stripe when a key is set. All other methods run in a clearly labelled demo mode until each provider is connected, so the full flow can be demonstrated without real money. Card numbers typed in demo mode never leave the browser.

5. AUTHENTICATION, SIGN-IN AND ONBOARDING
================================================================

5.1 Sign-in methods
- Continue with Google: the server verifies the Google ID token (audience, issuer, expiry, verified email) and uses a one-time state and nonce against replay attacks.
- Google One Tap: the "Sign in with Google" bubble in Chrome.
- University email code: the student types a student number (for example 202020280, and @aau.ac.ae is added automatically) or a full email. MANBAR emails a 6-digit code that is valid for 10 minutes and allows 5 tries. Only one new code per minute and at most 20 codes per network per hour can be sent. Codes are stored hashed.
- Password: after the first code sign-in a user can set a password. "Forgot password?" sends a reset code.
- Admin console login: a separate admin username and hashed password; 5 wrong passwords lock it for 15 minutes.

5.2 University and roster matching
- Only domains of active universities can sign in (Admin > Universities).
- A student-number email is matched with the official roster, which pre-fills full name, major, faculty and year. These become a "student" account.
- A name email (name.surname@aau.ac.ae) becomes a "teacher" account with a mentor profile.
- Admins import the roster as a CSV file (student_id, full_name, major, faculty, year_level).

5.3 Onboarding
New users complete a short onboarding before using the site: they confirm their name, then add a headline, a short bio, faculty, year, skills, interests and a profile colour theme. A guided product tour explains the main areas, and it can be completed or skipped.

5.4 Account bans
Banned users are signed out on their next click. When they try to sign in, they see the reason and the end date of the ban. Timed bans (24 hours, 3, 7 or 30 days) lift automatically when they expire.

6.1 Public landing page ( / )

- "Choose where you want to begin": six feature cards (Ask MANBAR AI, Projects, Marketplace, Learning center, Mentors, People). Each card has hover effects: a spotlight that follows the mouse, a glowing animated border, a light sweep, rising sparkles, a 3D tilt and floating artwork.
- Community feed board: quick buttons to share an idea, ask a question, find teammates, share a resource or show work; monthly statistics; trending hashtags.

6.4 Post page ( /post/{id} ), Saved ( /saved ), Search ( /search )
- A single post with all comments.
- Saved posts list.
- Global search across posts, people, projects, services and courses.

6.5 Profiles ( /profile/{id}, /me, /profile/edit ) and People ( /people )
- Cover image, avatar, headline, major, year, university and verified tick.
- Rank emblem with visual effects, plus name styles and profile effects.
- Statistics: followers and following (shown in a pop-up list), posts, projects, Rank XP and badges.
- "About" card with a banner header, bio, and contact buttons in brand colours (LinkedIn, GitHub, Discord, WhatsApp, phone, website).
- Skills and interests.
- Tabs: Posts, Projects, Services, Badges, Recommendations, Courses.
- Reputation card: league, stars, progress, trust %, badges and vouches.
- Verified recommendations: a user can recommend another only after real work together (a finished order, a finished project or a mentoring session).
- Follow, Message and "Report" (scam report) buttons.
- People directory: search by name, headline or student number, and filter by role (student or teacher), major and skill.

6.6 Projects ( /projects, /projects/new, /projects/{id} )
- Board with statistics, a "Matches my skills" section, tabs (Everything, Open to join, In progress, Completed, My projects), search, skill filter and sorting.
- Create a project from scratch or from an idea post, with a cover image.
- Roles: the owner lists the roles needed (for example "Backend developer", 2 places) with skills. Students apply for a specific role, and the owner accepts or declines.
- Team: members, task board (To do / Doing / Done), team chat, public updates.
- Roadmap: milestones with due dates that members tick off.
- Files: upload files and links. They are private to members until the project is completed, then public as proof of work.
- Status: open, in progress, completed (with the outcome).
- Vouches: teammates of a completed project rate each other (traits and comments). Each vouch gives Rank XP.

6.7 Marketplace ( /marketplace, /marketplace/new, /marketplace/{id}, /marketplace/orders, /marketplace/earnings )
- Two listing kinds: services ("I offer") and requests ("Looking for people", with a number of spots).
- Categories: Design and Creative, Programming and Tech, Writing and Translation, Tutoring and Study help, Video Photo and Audio, Business and Marketing, Other.
- Listing page details:
  - one price, or Basic / Standard / Premium packages;
  - delivery days, revisions and a "what you get" list;
  - skills and a cover image;
  - a portfolio of files, whole folders and links.
- Trust score out of 100, calculated from real orders, on-time delivery, response time, reviews, repeat clients and teammate vouches. Response time and "member since" are also shown.
- "Most trusted providers" ranking.
- Person-to-person order flow:
  1. The buyer sends a request, which opens a chat in Messages.
  2. The seller sends an offer: price, delivery days, and when to pay (before the work, 50/50, after delivery, or cash).
  3. The buyer accepts and pays if payment is due now. MANBAR holds online payments safely.
  4. The seller marks the order as delivered.
  5. The buyer confirms delivery and pays any remaining balance.
  6. The money is released to the seller's wallet.
  7. The buyer leaves a review.
- An order tracker shows each step.
- Wallet ( /marketplace/earnings ): available balance, money on hold, total earned, cash payments and payouts. Cash-out goes to a UAE IBAN or PayPal; only a masked account hint is stored.
- Reviews and ratings (1 to 5 stars), with a rating distribution.
- Admin "student view" and admin tools mode for managing any listing.

6.8 Checkout ( /checkout/course/{id}, /checkout/order/{id} )
- Secure checkout page with a live card preview and card validation: brand detection, Luhn check, expiry, CVC, and a "Use the test card" button.
- Methods: card (Visa, Mastercard, Amex), Apple Pay, PayPal, and tabby (4 interest-free payments with a schedule).
- Saved payment methods (from Settings > Billing) appear as one-tap options.
- Order summary with the service fee (free for AAU students), the payment terms and buyer protection.
- Admins and course hosts get a preview mode in which nothing is charged.

6.9 Learning Center ( /learn, /learn/my, /learn/new, /learn/{id} )
- Board with statistics, buttons (Browse courses, My courses, Quizzes and live, Create a course) and a "Most popular right now" strip.
- Course catalog with categories, search, free and paid courses, and cover pictures.
- Who can create courses: teachers, admins, and students who reached the Gold rank.
- Course content:
  - lessons (with YouTube, Vimeo or any video link);
  - summaries (short key-point pages);
  - quizzes;
  - files (PDF, Word, PowerPoint, Excel, text, images, ZIP; up to 25 MB each, several at once);
  - links.

- Sequential course path:
  - the host drags lessons, summaries and quizzes into any order;
  - students press "Start course" and follow the steps one by one, and each step opens when the previous one is done;
  - students can restart the path as many times as they like;

- Classmates panel: the other students enrolled in the course.
- Host tools: add lesson, summary or quiz; reorder; cover picture; settings; give access; delete.
- Host / student view switch, so the host can see the course as a student (joined or visitor).
- My courses ( /learn/my ): courses joined (with progress) and courses hosted (with student numbers).

- Course dashboard ( /learn/{id}/dashboard ) for the host:

6.10 Quizzes ( /learn/{cid}/quiz/... , /quiz/attempt/... )
- Question types: multiple choice and essay, with points, explanations, a time limit, a pass mark, an attempts limit and shuffling.
- Bulk import: paste text or upload a .docx / .txt file in a simple format (numbered questions, A)/B) options, * or "Answer:" to mark the right one, "Essay:" with "Keywords:"). A preview is shown before saving.
- Taking a quiz:
  - one question per screen;
  - answers save automatically;
  - a countdown submits automatically at zero;
  - multiple-choice questions are marked instantly;
  - essays with keywords are auto-marked, and other essays are marked by the host with feedback.
- Results page with the score, correct answers and the next step of the course.

6.11 Live quiz games ( /live, /live/{code}, /live/{code}/host )
- Kahoot-style live games:
  - the host starts a live quiz and shows a 6-digit code;
  - students join at /live;
  - everyone answers the same question at the same time;
  - a correct answer earns 500 points plus up to 500 more for speed;
  - the host sees a live leaderboard and a final podium.
- Quizzes hub ( /live ): open live games to join with one tap, all quizzes from joined or hosted courses grouped by course, recent attempts and scores, and statistics (quizzes available, taken, average, live now).

6.12 Mentorship ( /mentors, /mentors/{id}, /mentorship )
Mentor directory (teachers and experienced members), mentor profiles with expertise, mentoring requests, accept or decline, session scheduling, completion and feedback.

6.13 Direct messages ( /messages, /messages/{id} )

- Full notifications page: a banner with the number of new notifications, and filter chips by category (All, New, Social, Messages, Projects, Marketplace, Learning, Mentorship, Badges).

6.15 Settings ( /settings )
- Account: profile summary, university email, student ID, account type, member since, edit profile, sign out.
- Notifications: an on/off switch for each of the 7 categories.
- Billing and payments:
  - wallet balance;
  - saved payment methods shown as realistic Visa, Mastercard, Amex, PayPal and tabby cards, with make-default and remove;

6.16 Achievements and reputation ( /achievements )
- Rank XP formula = activity points + reactions received x 2 + comment reactions + marketplace review XP (5 stars = 100, 4 = 70, 3 = 35, 2 = 10) + project vouch XP + recommendation XP (rating x 12) + finished work (service 20, project 30, mentoring session 20).
- 8 leagues: Bronze (0), Silver (450), Gold (900), Platinum (1350), Diamond (1800), Legend (2250), Master (2700), Celestial (3150). Each league has 3 stars of 150 XP each, so there are 24 rank steps.
- Rank emblems with animated effects in the sidebar, on profiles and on the home page.
- 24 badges: Profile Pro, First Voice, Idea Machine, Conversationalist, Team Player, Project Leader, Service Pro, Five Star, Curious Mind, Graduate, Mentee, Rising Star, Centurion, Mission Complete, Community Hero, Knowledge Seeker, Guided Growth, Campus Connector, Gold League, Platinum League, Diamond League, Living Legend, MANBAR Master, Celestial.
- Trust percentage from the average of reviews, recommendations and vouches.
- Leaderboard and a rank-aware feed.

6.17 MANBAR Assistant (AI) ( /api/ai/assist, /api/ai/guide )
- Writing help on every writing surface: posts, comments and replies, projects, marketplace listings, courses and lessons, mentorship, profiles and messages.
- Grammar, spelling and vocabulary correction. Tones: natural, professional, academic, friendly and concise.
- A review card shows the polished text, the important before-to-after changes with short reasons, the engine used, and Apply / Keep buttons.
- Form drafting: generates a first draft of a project, service or course from a title.
- Smart routing: understands intent (for example "I'm good at frontend development" or "I want to help") and recommends ranked direct links to matching posts, open projects, people, mentors, courses and services, with honest "fit" labels.
- Page-aware guide ("Ask MANBAR AI").
- Works without any key through the local engine, and better with Gemini or Groq.

- Student roster ( /admin/roster ): add students, import a CSV, delete.
- Content ( /admin/content ): projects, services and courses, with publish and hide controls.
- Universities ( /admin/universities ): add universities and enable or disable sign-in per email domain.
- Settings and audit ( /admin/settings ): site notice, platform settings, and an audit log of every admin action.
- The admin sidebar supports the full and the icons-only modes.

6.19 Reporting and safety for members
- "Report" on posts, comments, projects and services. Reasons: spam, scam or fraud, harassment, inappropriate content, misinformation, cheating, other.
- "Report a scam" form on marketplace listings and profiles. The member chooses what happened (for example "Took my money and didn't deliver" or "Asked me to pay outside MANBAR"), links the order, enters the amount lost and describes the details. Money on hold stays frozen during the review.

9. SECURITY AND PRIVACY
================================================================

- University-only access: only active university email domains can sign in. Students are matched with the official roster.
- Google tokens are verified on the server: audience, issuer, expiry, verified email, one-time state and nonce.
- Email codes are hashed, expire after 10 minutes, allow 5 tries, and are rate-limited per email and per network. Passwords use PHP password_hash() (bcrypt).
- CSRF protection: every POST request needs a valid token (form field or X-CSRF-Token header). The only exceptions are Google and the Stripe webhook, which use their own signature checks.
- SQL injection protection: all queries use PDO prepared statements with parameters.
- XSS protection: all output is escaped with e() (htmlspecialchars).
- Security headers: X-Content-Type-Options: nosniff and X-Frame-Options: SAMEORIGIN.
- Upload safety:
  - the real file type is checked with finfo (MIME sniffing), with allow-lists and size limits;
  - random file names are used;
  - private files (course files, portfolios, project files) are stored in storage/, outside the public folder, and served by PHP only to allowed users (for example enrolled students or project members). Direct-message attachments are stored in public/uploads/messages with long random file names, so anyone with the exact link can open them; moving them to storage/ is listed as future work.
- Payments: card numbers and CVCs never reach the server in demo mode. Saved methods keep only the brand, the last 4 digits, the expiry and a masked hint. Payouts keep only a masked IBAN or PayPal hint.
- Permissions: each action checks the role and ownership (owner, member, host, admin). Admins cannot ban or demote themselves.
- Moderation: reports, scam cases, bans with reasons and lengths, and an audit log plus a per-user history of every admin action.
- AI privacy: API keys stay on the server, and only text explicitly sent by the user goes to a provider. The assistant is rate-limited.
- Configuration: secrets live in config/config.local.php or environment variables, never in Git. In production, error display is off, and the demo login and on-screen codes are disabled.

12. INSTALLATION AND DEPLOYMENT
================================================================

Local:
1. Install XAMPP (PHP 8.1 or newer) and start Apache and MySQL.
2. Put the project in C:\xampp\htdocs\manbar.
3. Import database/manbar.sql in phpMyAdmin, or run: php database/install.php --demo
4. Open http://localhost/manbar/public/

Server:
- Requirements: PHP 8.1+, MySQL/MariaDB, Apache with mod_rewrite (or Nginx), and HTTPS.
- Set the document root to public/.
- Create config/config.local.php with the database, mail, Google, AI and Stripe settings. Set env = production and keep dev_login off.
- Make public/uploads/ and storage/ writable by PHP.
